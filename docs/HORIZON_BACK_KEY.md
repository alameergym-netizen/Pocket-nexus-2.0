# B / Back isolation

User reported B sometimes opens Nexus Control on RP6. Existing matchesBack accepted Android KEYCODE_BACK without checking fallback, virtual flags or physical scan. Android may synthesize Back from B when it is unhandled; exact user event trace not available. Shared matching now excludes B, Linux face-button scans, mouse, fallback/virtual events and ambiguous scanless auto Back. Explicit calibration stores key+scan where available, old k:4 and s: mappings remain readable. Console consumes B as normal back after modal handlers and before Android fallback, and opens Control only for matched noncancelled physical press/release. Global service uses same dedicated Back matcher and matching release; Game's existing matcher also benefits without changing Guide/M1/M2 settings. Android 13 emulator control test explicitly maps F8 because adb synthetic Back has no hardware scan, and checks B does not open Control. Seven tests exercise input policy. Physical RP6 Button Test required to confirm actual dedicated Back scan; if firmware emits identical key/scan for B and dedicated Back, app cannot distinguish them, so recalibrate or change firmware mapping. No claim of physical fix until verified. Existing #38/#39 candidates independent, fresh combined CI required.
