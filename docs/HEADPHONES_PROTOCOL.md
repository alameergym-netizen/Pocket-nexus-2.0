# Headphones Center: readback foundation

Scope: experimental native Android integration, initially Huawei FreeBuds 7i; no hardware support is claimed yet.

## Provenance
- Nexus root LICENSE.txt is GPLv3. LibreBuds and HuaweiPods GitHub metadata identify GPL-3.0. Keep attribution and corresponding source obligations; review any separately licensed assets/dependencies before importing. No third-party artwork or privileged hook code is included.
- LibreBuds [pinned source](https://github.com/librebuds/librebuds/tree/c7b0833e73e15c427719ed2b684060a98f67cb75): README lists FreeBuds 7i under expected basic support, not confirmed. The public Android RFCOMM SPP implementation is in android/app/src/main/java/io/github/librebuds/bt/RfcommLinkFactory.kt. The packet, single-frame CRC, battery and ANC formats and known non-7i test vectors are under android/protocol. This new Java codec follows that documented framing and independently rejects ambiguous/truncated/duplicate TLVs, unsupported flags, invalid CRC, out-of-range battery values and unknown mode values. Source attribution also retained in the Java file. The 7i transport and exact firmware response are unverified.
- HuaweiPods [pinned source](https://github.com/Nshpiter/HuaweiPods/tree/e2cf07eda48575c718d0568c0d762c029835bbea): HuaweiFreeBuds7iController.kt documents 7i-specific captured commands for wear detection, spatial audio, high-quality audio, head motion, ten-band custom EQ and dual devices. It routes through its own HuaweiL2capAncController and route policy. This is research evidence, not proof these features work through ordinary Android RFCOMM on RP6. Do not transplant HyperOS/LSPosed hooks or assume the transport/framing for larger or fragmented packets is interchangeable.

## Included in this patch
Pure Java complete-single-frame read-only queries and decoders for battery and reported noise mode. A valid packet is not a verified model or proof of a successful command. Unknown/missing values remain null, no invented percentages or charging status. No transport, permission change, UI integration, ANC writes, retry loop or persistent service in this patch. The decoder is not a byte-stream reassembler; callers must use a bounded, validated framing layer, with fragments rejected until supported.

## Next adapter contract (Codex)
- User explicitly chooses an already-paired device; no scan, automatic pairing or takeover. Verify model from device-info response, not name alone. Android Bluetooth CONNECT permission, unavailable/denied states and official AI Life / LibreBuds fallback.
- Public Android BluetoothSocket transport, one session/worker and one request at a time, bounded frame reassembly, deadline that closes socket to unblock I/O, owner generation to reject stale results, no unbounded buffer/queue/reconnect. Reject unsupported dialect/fragmentation rather than guess. Do not log MAC or private device identifiers.
- Read battery and reported noise state first. Separate unknown from zero/off. Once verified on the exact model, expose explicit ANC/off/awareness user writes only with matching acknowledgement **and** fresh state readback; timeout or mismatch must not update the displayed state optimistically. Do not write level/submode unless model-specific evidence exists. Never force firmware updates, codec or device removal.
- UI (Claude): controller and touch equivalent actions, permission/connection/unknown states; current AudioTrack route and Nexus stream EQ distinct from earbud hardware EQ. No fabricated indicators. Preserve B/Back/Guide semantics, themed layout, large text and accessibility.
- Unit fixtures for wrong device, stale session, malformed frames, partial reads, disconnect, timeout and lost ACK. Emulator verifies permission and UI, not actual Bluetooth. Final acceptance on RP6 Android 13 and FreeBuds 7i firmware: observed left/right/case with absent/closed case, three ANC modes compared against actual device, reconnect, competing app, no stream interruption. Further capabilities only when verified. No Root or hidden API requirement.

## Experimental transport increment
- Public Android SPP probe with process-wide single-flight lease, explicit bonded-device selection, 12-second deadline and socket-close cancellation. No UI entry or manifest edit yet; requires the #122 permission work. Model suffix 000163 is a conservative LibreBuds 7i profile match, not independently confirmed on RP6 or cryptographic attestation. Unknown identity stops further queries. Bounded single-frame reads only. No setting writes. Synthetic fixtures do not establish hardware compatibility. A blocked platform call retains the lease; no overlapping probe or unbounded reconnect is allowed.

## Experimental 7i noise command increment
HuaweiPods pinned HuaweiAncLevelProfile.kt maps adaptive=1, light=0, balanced=2, deep=3 for 7i (different from 6i), awareness transition=FF. Fixed CRC-checked command vectors are from pinned HuaweiAncPackets.kt; LibreBuds Anc.kt requires ACK plus reread. Added explicit experimental startNoiseChange API, no UI invocation or automatic write. The same socket must first return recognized model and valid current state; exactly one fixed setting write; ACK status zero and fresh matching readback are both necessary (including exact ANC level). Existing matching state returns ALREADY_SELECTED without writing. Timeout/cancellation/failed confirmation never imply no device-side change: refresh before further action. Malformed CRC, unknown current ANC level, unsupported model and invalid battery values remain unavailable. Seven synthetic transaction tests, not RP6 evidence. Physical 7i validation remains required before exposing a normal user control.
