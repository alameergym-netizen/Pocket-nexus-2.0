# G05 Adaptive reconnect guard
Distinct POOR episodes, not repeated reports, count toward flapping. Sustained deadline is anchored to first POOR after warmup; healthy reports cancel it; unknown status is not treated as healthy. Ignore stale Game activity callbacks and clear timers on stop. Three adaptive reconnects maximum per carried resume budget; manual bitrate reset still resets steps. No new automatic features, codec or bitrate floor changes. This is a conservative engineering guard against unnecessary reconnects, not proof of a fix for actual RP6 frame stutter. Six pure policy tests; physical measurements and streaming quality comparison remain pending. Integrated candidate on #50 after checking existing CI; combined CI required.

## Upstream streaming research on 2026-11-25

- KAST is a GPL-3.0 Artemis fork with work in progress on retaining the stream during short outages and restoring it when the connection has died. Vibepollo 2.18.9 documents the upstream `control_peer_timeout` option. Compare bounded network interruptions on the target setup and record when the existing session survives versus when the client starts a new one. Keep the host's configured timeout under the owner's control. ## MediaCodec timing observations

Input timing records use a fixed 256-entry per-decoder buffer shared by the input and output threads. Recording before queueing allows an immediate output to find its timestamps. Failed input is discarded, and codec recovery clears old records. The in-stream loss percentage divides missing frames by the expected frame count, which already includes those frames. Measure real decoder time, frame pacing and recovery on RP6 with the final streaming setup.
