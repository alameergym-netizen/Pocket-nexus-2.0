# Nexus Host development delivery

Windows CI will package only the explicit helper files, the read-only Android upgrade preflight, and documentation after its existing loopback tests succeed. The ZIP has an internal SHA-256 manifest and a separate archive hash. This detects corruption; a hash published alongside a file does not independently authenticate its publisher. It is not an MSI, a code-signed installer or a Windows service. Never distribute CI test fixtures, private settings, token files or a signing key.

Extract to a stable local directory. Read README.txt before running PocketNexus-PC.bat. Existing helper storage and startup behavior are retained; no automatic installer, data migration, autostart change or new network endpoint is introduced by the packaging code. Keep your prior helper directory until the new version is verified. Stop the old helper using its existing tray Quit before starting the candidate, and do not change the installed Vibepollo host. APC1 control remains plaintext; use trusted private networks or encrypted overlay only.

Use a trusted copy of `Stage-NexusHostDev.ps1` with `-Archive` and `-ExpectedSha256` from the corresponding CI run to verify the Windows development archive. With no `-StageRoot`, verification reads the ZIP, its manifest and every file. With `-StageRoot`, it writes a separate versioned directory after verification and refuses to replace a prior stage. An interrupted staging operation leaves any existing installation in place. Starting the companion remains a manual step. Windows CI exercises side-by-side staging and rejects an incorrect ZIP digest, a modified file, a duplicate and an invalid path.

Optional Android preflight: from a Windows PowerShell terminal, run Test-NexusUpgrade.ps1 with -Apk and trusted Android SDK paths for -Adb, -Aapt and -ApkSigner. If multiple devices are attached, select -Serial locally. Authorize USB debugging only on your trusted computer. It reads the installed base APK into a temporary directory, verifies both APK signatures and compares package, current signer set and version code. It never calls install/uninstall/clear. It rejects signer mismatch, different package and non-newer version, and does not prove actual installation or settings compatibility. The extracted base APK is deleted in a finally block. Run -SelfTest without a device to test policy. Fresh installs require a separate procedure.

G01 remains pending owner signing and physical upgrade/migration checks. Windows production installer, signed distribution, actual GUI validation, encrypted transport and host compatibility remain release work.
