# Nexus Host development delivery

Windows CI packages the explicit helper files, delivery tools, read-only Android upgrade preflight and documentation after existing loopback tests succeed. The ZIP has an internal SHA-256 manifest and a separate archive hash. Establish the source of the expected SHA-256 separately from the ZIP when verifying publisher provenance. Never distribute CI test fixtures, private settings, token files or a signing key.

For manual setup, extract to a stable local directory and read README.txt before running `PocketNexus-PC.bat`. Keep your prior helper directory until the new version is verified. Stop the old helper using its tray Quit before starting the candidate. APC1 control remains plaintext and is limited to trusted private networks or an encrypted overlay.

Use a trusted copy of `Stage-NexusHostDev.ps1` with `-Archive` and `-ExpectedSha256` from the corresponding CI run to verify the Windows development archive. With no `-StageRoot`, verification reads the ZIP, its manifest and every file. With `-StageRoot`, it writes a separate versioned directory after verification and refuses to replace a prior stage. An interrupted staging operation leaves any existing installation in place. Starting the companion remains a manual step. Windows CI exercises side-by-side staging and rejects an incorrect ZIP digest, a modified file, a duplicate and an invalid path.

### Per-user development installation

Use the trusted `Install-NexusHostDev.ps1` and `Stage-NexusHostDev.ps1` from the same tested revision in one directory. In Windows PowerShell, pass the ZIP and its expected hash to `Install-NexusHostDev.ps1 -Archive <zip> -ExpectedSha256 <sha256>`. The script installs a version by ZIP hash under `%LOCALAPPDATA%\PocketNexus\NexusHost-dev` and adds a version-specific Start menu shortcut. It runs without elevation. Installation leaves the companion stopped and preserves existing startup, firewall, Vibepollo and Companion settings. The Start menu shortcut starts the normal tray helper directly. Quit the old helper first through its tray menu. Multiple versions can be installed for rollback and use the existing settings for the current Windows user.

Quit the version and turn off its Start with Windows option before running `Install-NexusHostDev.ps1 -Remove -ExpectedSha256 <sha256>`. Removal checks that the installed files still match the original manifest and identifies the exact Start menu shortcut. If an added or changed file is present, move it to a separate folder or restore the original package file before retrying. Companion settings remain under `%LOCALAPPDATA%\ArtemisPocket`. Running the install again with the same archive repairs a missing shortcut for the verified version. CI tests on Windows use an isolated temporary Start menu and installation directory. A production signed installer and a manual desktop launch remain release requirements.

Optional Android preflight: from a Windows PowerShell terminal, run Test-NexusUpgrade.ps1 with -Apk and trusted Android SDK paths for -Adb, -Aapt and -ApkSigner. If multiple devices are attached, select -Serial locally. Authorize USB debugging only on your trusted computer. It reads the installed base APK into a temporary directory, verifies both APK signatures and compares package, current signer set and version code. It never calls install/uninstall/clear. It rejects signer mismatch, different package and non-newer version, and does not prove actual installation or settings compatibility. The extracted base APK is deleted in a finally block. Run -SelfTest without a device to test policy. Fresh installs require a separate procedure.

### Optional Windows save preview

From Windows PowerShell, run `Get-NexusSavePreview.ps1 -Ludusavi <path-to-ludusavi.exe> -Action Backup -Game <exact-game-title>` to see which local saves differ from the configured backup. Use `-Action Restore` to compare a configured backup with the live saves. The output shows counts of files and registry keys and flags differing or removed entries without printing paths. The helper runs one preview and disables cloud synchronization and manifest update checks. It uses the local Ludusavi installation and its configuration. Actual backup and restore remain separate actions in Ludusavi. [Ludusavi v0.31.0 CLI](https://github.com/mtkennerly/ludusavi/blob/v0.31.0/docs/cli.md)

G01 remains pending owner signing and physical upgrade/migration checks. Windows production installer, signed distribution, actual GUI validation, encrypted transport and host compatibility remain release work.
