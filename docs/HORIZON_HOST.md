# Nexus Host protocol hardening candidate

The existing Windows PowerShell/C# helper is retained, not replaced by a new streaming server.
- Require exact APC1 handshake and complete strict UTF-8 line framing; maximum 1023 payload bytes, optional final CRLF, no embedded CR/NUL, no partial EOF.
- A 15-second maximum whole-line read deadline prevents indefinite slow-drip framing. Bound helper workers to 16 concurrent clients. The USB streaming tunnel and microphone wire protocol are unchanged.
- Windows self-test runs on loopback only, with synthetic Steam fixtures and malformed-handshake checks. New Windows CI compiles and exercises the original helper on a Windows runner.
- Legacy authentication remains unchanged: loopback is trusted, LAN tokens and PINs are plaintext. Do not expose the helper directly to the internet. Use trusted private networks or an encrypted overlay. This is not TLS, authenticated host identity, a full replacement for Apollo/Vibepollo, or a new signed Windows executable.
- The host candidate is independent of the pending Android Buds update. Both must pass integration validation before adoption.

## Integrated client candidate
Windows candidate passed all 32 self-test checks in run 45416055139. This candidate starts from the verified 128-test Buds baseline, retains those Windows changes, and requires strict UTF-8 response frames, explicit 0/1 handshake flags, expected hex token replies and a whole-frame read deadline on Android. Five additional Android protocol tests. Deadlines are per response line, not entire multi-line query; no TLS or server identity proof is added. Integrated Android and Windows CI required.

## Windows desktop dashboard candidate
Nexus Host is a first-class Windows application alongside Android, not a replacement for Vibepollo. This milestone adds a non-modal local WinForms status window launched from the existing tray menu or double-click. It displays companion listener, port, USB bridge/ADB status, PC library initialization, stream-host listener detection and autostart; manual refresh and explicit PIN copy. No PIN in dashboard summary, but the legacy tray and status storage remain unchanged. No new network endpoints or Windows privileges. Six synthetic USB status checks extend the existing loopback self-test. Windows CI must pass, then manually verify window open/close, refresh, DPI scaling, keyboard navigation, PIN copy and existing tray/stream behavior on the real Windows machine. A listening port does not prove Vibepollo interoperability.

Remaining Windows release gates: secure authenticated transport and host identity, revocable device pairing, credential storage, allowlisted actions, Vibepollo capabilities/version negotiation, Playnite/library adapters, telemetry, save vault and verified file transfer, installer/uninstaller and signed upgrade, recovery, and integrated RP6/Windows testing. Keep all existing USB, mic, power and library paths working. The dashboard is not yet the final desktop design.

## Encrypted host status and independent device access
The Windows tray can enable an IPv4 TLS 1.2 listener on TCP 47111. The handheld verifies a SHA-256 certificate fingerprint transferred directly from the PC before sending a dedicated random device key. Windows retains a non-exportable Current User certificate and saves only certificate-bound key digests. Each named device can be revoked or have its key replaced. Status exposes CPU and RAM usage, uptime, and battery and AC information. The listener starts disabled and has no privilege changes or automatic firewall rule. The Windows loopback test exercises TLS, mismatched certificates, independent credentials, plaintext rejection, and persistent revocation. The PC card's Secure host status action uses the existing network address and only saves a code after a verified response.

Power, library, microphone, USB and streaming continue through their existing connections. G08 and G10 still need secure coverage for those applicable operations, a private-network Windows-to-Android acceptance run, and a signed installer. Direct internet exposure of plaintext APC1 remains prohibited.

### Upstream integration research on 2026-11-25
- Vibepollo 2.18.9 is GPL-3.0. Its API documents HTTPS and fine-grained per-path and method tokens, including read-only apps and separate authenticated write actions. A first adapter can query the local host with a scoped read-only token stored on Windows and publish a narrow status view to Android. Do not depend on the administrator password or relay arbitrary API paths. [Vibepollo API](https://github.com/Nonary/Vibepollo/blob/2.18.9/docs/api.md)
- Playnite 10.65 is MIT. The SDK exposes a game collection through the database interface. A local extension can export stable game identifiers and metadata using the SDK rather than guessing at the database format. Steam, Epic, and GOG integrations must remain available. [Playnite SDK database interface](https://github.com/JosefNemec/Playnite/blob/10.65/source/PlayniteSDK/Database/IGameDatabase.cs)
- Vibepollo documents PyroWave negotiation and bitstream-version constraints. Standard Moonlight continues to use H.264, HEVC, and AV1. Keep those paths for G05 and require a compatible decoder and measured Windows/Android results before claiming PyroWave support. [Vibepollo PyroWave protocol](https://github.com/Nonary/Vibepollo/blob/2.18.9/docs/pyrowave-protocol.md)

## Vibepollo status in the Windows dashboard
The dashboard can verify and save a connection to the local management API, then refresh host version, cached encoder capabilities and virtual display driver status. The owner chooses the public certificate from the local installation and a token limited to GET /api/metadata. Nexus Host pins that certificate and keeps the token in Current User protected storage. A failed verification leaves existing settings in place. Refresh queries fixed loopback HTTPS and follows no redirects. Missing readiness data is shown as unknown. The adapter never starts a probe, stream or configuration update. The Windows loopback tests simulate the documented endpoint. Real Vibepollo compatibility and Android delivery of this metadata remain open. [Vibepollo API](https://github.com/Nonary/Vibepollo/blob/2.18.9/docs/api.md) · [Certificate configuration](https://github.com/Nonary/Vibepollo/blob/2.18.9/docs/configuration.md#cert)

## Optional USB-only legacy control
Windows tray settings can scope legacy APC1 to loopback at the next restart. ADB reverse continues to reach it. Existing installations stay on their current Wi-Fi default until the owner chooses USB-only. The dashboard reports the actual bind scope and whether a restart is pending. The toggle changes the listener bind, with no firewall update or change to the encrypted status and streaming ports. The Windows self-test checks the bind address on an isolated socket and preserves the synthetic USB reverse mappings.

## Device-scoped secure game list
The Windows tray can issue a status-only key or a status-and-game-list key. Existing status keys retain their original scope. Android verifies the saved certificate before either request. The new request returns a bounded, counted list of game names, local catalog sources and installed flags. It omits paths and launch commands. It does not launch, install, reconfigure, or change the legacy PC library. Keys can be independently revoked or reissued in the tray. The Android list is built only from a complete authenticated reply, without a cached fallback. Physical LAN pairing and migrations remain part of acceptance.
